iPhone から Muse に指示して進める、AI主導開発の専用ワークスペース。正本は GitHub リポジトリ、方式はハイブリッド型（段階昇格型）。

現状版 2026-11-08 Public showcase

アーキテクチャ図（現在の仕組み）

ユーザー / iPhone実装済み音声入力・チャットで依頼し、通知と成果物を確認して判断・承認する。ログインと二段階認証は本人。
Muse VM (Linux)実装済み専属エージェント。チャット / ファイル / ターミナル / ブラウザ / スキル / cron。記憶（MEMORY・日次ログ・ゴール）を持つ。
GitHub: ai-dev-workspace実装済み開発の正本（private）。ブランチ → PR → 承認 → マージ。運用はプレイブックと AGENTS.md の規約。

試作: Muse スペース実装済みプロトタイプやダッシュボードを速く作る場所。育てると決めたら GitHub へ昇格する。
Google 6サービス接続済みGmail / Drive / Sheets / Docs / Slides / Calendar。仕様・資料・予定・メールの置き場。

承認と安全の境界

送信・公開・削除・支払い・マージは本人の承認を経る。秘密情報はコミットしない。読み取りは広く、書き込みは狭く（ブランチ + PR 経由）。

セットアップの流れ

  1. 入口を用意する — iPhone に Muse を入れ、ログインする。以後の操作はすべて iPhone から。
  2. Google 6サービスを接続する — Gmail / Drive / Sheets / Docs / Slides / Calendar。すべて同じアカウントで接続し、状態を再確認する。
  3. GitHub を接続する — OAuth 認証のあと、Muse の GitHub App をインストールし、アクセスできるリポジトリの範囲を設定する。
  4. 専用リポジトリを作り土台を入れる — リポジトリ作成は GitHub 上で本人が行い（連携に作成権限はない）、App の対象に追加。README / AGENTS.md / .gitignore / docs を最初のコミットで投入する。
  5. 運用ルールを PR で入れる — プレイブック（昇格基準・チェックリスト）をブランチ → PR → 承認 → マージで導入し、PR 運用を1周させる。
  6. ホームページと構成図を置く — README が GitHub 上の顔。詳細は docs/architecture.md と docs/setup.md、このページは GitHub Pages 用ソース。
  7. 日常運用を始める — 作りたいものを伝える → 仕様 → 承認 → 実装 → PR → 承認 → マージ。
